# 联调验证指南

本文档说明如何使用 NDI 官方工具验证 NDISender / NDIReceiver Demo。

## 前置条件

- [ ] 已安装 [NDI Tools 6.3.x](https://ndi.video/tools/)
- [ ] 已构建 Demo（Release x64）
- [ ] `Processing.NDI.Lib.x64.dll` 与 exe 同目录
- [ ] 本机防火墙允许 NDI 通信（局域网）

## 测试 1：官方工具链路（基线）

验证本机 NDI 环境正常。

1. 启动 **NDI Screen Capture**（系统托盘）
2. 启动 **NDI Studio Monitor**
3. 右键 Studio Monitor → 选择本机 Screen Capture 源
4. **预期**：看到桌面画面，听到系统音频

## 测试 2：NDIReceiver 拉流

验证 Receiver 发现、连接、DX11 渲染、SDL2 音频。

1. 启动 **NDI Test Patterns**（或 Screen Capture）
2. 启动 **NDIReceiver.exe**
3. 点击 **刷新源** → 选择 Test Patterns 或 Screen Capture
4. 点击 **连接** → **开始接收**
5. 调整参数：
   - **Fastest**：最低延时色彩格式
   - **Frame Sync**：平滑播放（延时略增）
   - 取消 **启用音频**：仅视频
   - 取消 **启用视频**：仅音频
6. **预期**：
   - 预览窗口显示测试图/桌面
   - 统计区视频帧计数递增
   - 丢帧数为 0 或接近 0

## 测试 3：NDISender 推流（High Bandwidth）

1. 启动 **NDI Studio Monitor**
2. 启动 **NDISender.exe**
3. 选择显示器 → 模式 **High Bandwidth** → **发送色彩格式** 可选 BGRA/BGRX/UYVY/UYVA → **开始推流**
4. Studio Monitor 中选择 `NDISender Demo` 源
5. **预期**：低延时桌面画面；系统音频（若启用）；状态栏显示 **发送 FourCC**

### 发送格式组合建议（与 NDIReceiver 联调）

| Sender 发送格式 | Receiver Fastest 典型收到 | Alpha 测试 |
|-----------------|---------------------------|------------|
| BGRA | UYVY 或 UYVA | 可用 |
| BGRX | 不透明路径 | 无 Alpha |
| UYVY | UYVY | 无 Alpha |
| **UYVA** | **UYVA** | **推荐**（少一次 SDK 转换） |

> **像素格式说明**：NDISender 内部采集仍为 BGRA，High Bandwidth 下可在 UI 选择提交给 SDK 的 FourCC。NDIReceiver 默认 `Fastest` 时收到格式仍取决于接收端 `color_format`（见 [04 §5.1](04-开发计划与架构设计.md#51-推拉流视频像素格式关系)）。预览偏色时检查 `frame.FourCC` 与渲染路径是否一致。

## 测试 4：NDISender HX 模式

1. NDISender 模式选 **HX H.264**
2. 调整 **HX 码率倍率**（0.1–2.0）
3. 与 **NDI Screen Capture HX** 对比画质与带宽
4. 使用 **NDI Discovery**（NDI Tools）查看 codec 信息

> HX 模式依赖 Windows Media Foundation H.264 编码器；若初始化失败，请安装 H.264 编码功能或使用 High Bandwidth 模式。

## 测试 5：跨版本互通

若网内有 NDI 5 设备：

1. NDI 5 源 → NDIReceiver（NDI 6 SDK）应可连接
2. NDISender → NDI 5 Studio Monitor 应可观看

## 测试 6：Alpha 透明度推拉流

验证带 Alpha 通道的 NDI 流能否正确传输，并在接收端可视化/导出。

### 发送端

1. 启动 **NDISender.exe**
2. 视频源选 **Alpha 测试图**（默认 1280×720）
3. **发送色彩格式** 选 **UYVA**（切换至 Alpha 测试图时 UI 会自动默认 UYVA）
4. 调节 **测试图 Alpha** 滑动条（0–100%），推流过程中可实时改变；状态栏 **发送 Alpha: min~max** 反映 BGRA 源采样
5. 发送模式 **High Bandwidth**（测试图模式会自动锁定）
6. 点击 **开始推流**；状态栏应显示 **发送 FourCC: UYVA**

测试图内容：四边不透明标识条、中心半透明圆、不透明方块、移动半透明圆，其余区域 **alpha=0**（全透明）。

> Sender 无本地预览。若 Receiver 统计 **Alpha: 255~255** 且预览 Alpha=100%，说明 NDI 未保留透明，请用 Receiver「预览 Alpha 倍增」验证混合，或改用 Fastest + 关硬件解码。

> HX H.264 模式不保证 Alpha 透传，透明度测试请使用 High Bandwidth。

### 接收端

1. 启动 **NDIReceiver.exe**
2. 点击 **Alpha 测试预设**（自动选择 `Fastest`、关闭硬件解码，并启用棋盘格背景）
3. 刷新源 → 选择 `NDISender Demo` → **开始接收**
4. 拖动 **预览 Alpha 倍增** 滑动条（例如 50%）观察棋盘格混合；此控件仅影响预览，用于验证渲染混合是否正常（混合实现见 [07-NDIReceiver预览渲染与Alpha混合](07-NDIReceiver预览渲染与Alpha混合.md)）
5. **预期**：
   - 透明区域透出 **棋盘格背景**
   - 半透明区域与棋盘格混合
   - 统计区 **FourCC: BGRA**（由 UYVA 转换）或 **UYVA**，**Alpha: 0~255** 且最小值应明显小于 255
6. 点击 **保存当前帧 PNG...**，导出当前 BGRA 显示帧

> 带 Alpha 的 SpeedHQ 流在 `Fastest` 下通常以 **UYVA** 原生交付，Alpha 通道保留更完整。`BGRX/BGRA` 经 SDK 转换后 Alpha 可能被填为不透明；**请关闭硬件解码**。

### PNG Alpha 查看与验证

导出 PNG 后，用下列工具确认透明与 Alpha 通道是否正确。

#### 快速查看透明效果（棋盘格 / 半透明）

| 软件 | 适用场景 |
|------|----------|
| [GIMP](https://www.gimp.org/) / [Photopea](https://www.photopea.com/) | 免费；透明区显示棋盘格，**推荐首选** |
| Chrome / Edge / Firefox | 拖入 PNG 即可预览透明；**不能**单独查看 Alpha 通道 |
| [IrfanView](https://www.irfanview.com/) / [XnView MP](https://www.xnview.com/en/xnviewmp/) | 轻量预览透明 |
| Photoshop / Affinity Photo | 专业通道查看 |

> **Windows「照片」** 等系统默认看图器常将透明区显示为黑色或白底，易误判为「无 Alpha」，请勿单独依赖。

#### 单独查看 Alpha 分量（灰度通道）

需要确认 Alpha 数值分布（是否全 255、是否存在 0~255 渐变）时：

- **GIMP**：`窗口 → 通道`，选择 **Alpha** 通道
- **Photoshop / Photopea**：`窗口 → 通道`，点 **Alpha**
- **Affinity Photo**：Channels 面板查看 Alpha

灰度含义：**白** = 不透明，**黑** = 全透明，**灰** = 半透明。

#### 命令行（ImageMagick，可选）

已安装 [ImageMagick](https://imagemagick.org/) 时可用于批量或脚本化检查：

```bash
magick input.png -alpha extract alpha_only.png
magick input.png -format "%[opaque]" info:
```

`alpha_only.png` 为提取出的 Alpha 灰度图；第二条命令可快速查看是否含非不透明像素。

#### 与 NDIReceiver 对照

- 用浏览器或 GIMP **快速确认** PNG 是否存在透明区域
- 用 GIMP / Photopea 打开 **Alpha 通道**，核对是否与 Receiver 统计 **Alpha: min~max** 一致
- 若统计为 **Alpha: 255~255** 但预览能看到棋盘格，说明是「预览 Alpha 倍增」混合效果，**不代表** NDI 已成功透传透明

### 对照实验

| 操作 | 预期现象 |
|------|----------|
| 取消「透明检测背景」 | 透明区域显示为黑色/底色，难以判断 Alpha |
| 色彩格式改 `BGRX/BGRA` + 硬件解码 | Alpha 可能丢失，统计区 Alpha 可能为 255~255 |
| 屏幕采集推流 + 棋盘格 | 几乎全不透明，棋盘格不可见 |

## 常见问题

| 现象 | 排查 |
|------|------|
| 源列表为空 | Access Manager 检查组/网卡；确认 NDI Tools 能看到源 |
| 预览黑屏 | 检查 color_format；尝试 UYVY_BGRA |
| 预览偏色（洋红/粉） | 发送 BGRA 不等于接收 BGRA；Fastest 通常交付 UYVY，确认渲染按 `frame.FourCC` 处理；或改选 BGRX/BGRA |
| Alpha 测试看不到棋盘格 | 确认 Sender 为 Alpha 测试图；Receiver 用 BGRX/BGRA；FourCC 应为 BGRA |
| 收到 BGRX 是否正常 | 选 **BGRX/BGRA** 且不透明内容（如屏幕采集）时为预期；Sender 提交 BGRA 仍可收到 BGRX；要 Alpha 用 Fastest+关 HW 解码或确认 FourCC 为 BGRA/UYVA |
| 保存 PNG 失败 | 仅 BGRA 帧可保存；检查色彩格式与是否正在接收 |
| PNG 透明区显示为黑色 | 换用 GIMP、Photopea 或浏览器打开；勿用 Windows「照片」等忽略 Alpha 的看图器 |
| 界面拖动/操作卡顿（收流中） | 确认已用新版预览路径；检查硬件解码与 CPU 占用 |
| 界面拖动/操作卡顿（未连接/空闲） | 源发现不得在 UI 线程阻塞；自动刷新应走后台线程（250ms 等待） |
| DXGI 采集失败 | 以普通用户运行；排除全屏独占游戏 |
| DLL 加载失败 | 复制 `Processing.NDI.Lib.x64.dll` 到 exe 目录 |

### color_format 选型速查

| 目标 | 建议 color_format | 说明 |
|------|-------------------|------|
| 最低延时 / 最高性能 | Fastest | 通常收到 UYVY；渲染需支持 YUV |
| 应用需要 BGRA 像素缓冲 | BGRX/BGRA 或 UYVY/BGRA | SDK 做色彩转换，有一定开销 |
| 最高画质 / 16-bit | Best | FourCC 可能为 P216/PA16 等，需广泛支持 |
| 验证 Alpha 透传 | Fastest + 关硬件解码 | 有 Alpha 时常为 UYVA；见 §5.1 BGRX/BGRA 说明 |

### BGRX 与 Sender BGRA 不一致

- **BGRX 不含可用 Alpha**；第 4 字节 X 为填充，常见 255，但不应作为透明度。
- 仅当 Receiver 色彩格式为 **`BGRX/BGRA`** 且 NDI 判定源流**无 Alpha** 时，才会收到 **BGRX**；默认 **Fastest** 时多为 **UYVY/UYVA**。
- **NDISender High Bandwidth 始终提交 BGRA**，但 Receiver 可能收到 UYVY、BGRX、BGRA 等 — 以统计区 **FourCC** 为准，详见 [04 §5.1 BGRX 与 BGRA](04-开发计划与架构设计.md#bgrx-与-bgra含义及何时收到-bgrx)。

详细机制见 [04-开发计划与架构设计 §5.1](04-开发计划与架构设计.md#51-推拉流视频像素格式关系)。

## Access Manager 快速配置

1. 打开 **NDI Access Manager**
2. **Advanced** → 选择正确网卡
3. 大型网络：配置 Discovery Server IP
4. 修改 `%ProgramData%\NDI\ndi-config.v1.json` 后重启 Demo
