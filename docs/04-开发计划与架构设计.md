# 开发计划与架构设计

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                        NDISender                            │
│  Qt UI → DXGI Capture / AlphaTestPattern → [HW Encoder] → NDI Send │
│         → WASAPI Loopback ────────────→ NDI Audio            │
└─────────────────────────────────────────────────────────────┘
                              │ NDI (LAN)
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                       NDIReceiver                           │
│  Qt UI → NDI Recv → [UYVA→BGRA] → [Frame Sync] → DX11 Render  │
│                   → SDL2 Audio Playback                      │
└─────────────────────────────────────────────────────────────┘
```

### 5.1 推拉流视频像素格式关系

**结论**：拉流端实际收到的像素格式，取决于接收端在 `NDIlib_recv_create_v3` 时设置的 `color_format`，**不是**发送端 `FourCC` 的直通。

| 环节 | API / 字段 | 作用 |
|------|------------|------|
| 发送 | `NDIlib_video_frame_v2_t.FourCC`（本项目 High BW 为 BGRA） | 告诉 SDK **应用提交给它的原始缓冲格式** |
| 接收 | `NDIlib_recv_create_v3_t.color_format` | 告诉 SDK **希望交付给应用的格式** |

发送 BGRA 只是输入格式；NDI 内部会以 SpeedHQ 等路径压缩/传输。接收端 `color_format` 才是输出格式偏好。官方文档（[NDI-RECV](https://docs.ndi.video/all/developing-with-ndi/sdk/ndi-recv)）：

> `color_format` — This parameter determines what color formats you are passed when a frame is received.

#### 各 color_format 与 BGRA 发送端

| 接收端 `color_format` | 无 alpha 时常见交付 | 有 alpha 时常见交付 |
|----------------------|---------------------|---------------------|
| `NDIlib_recv_color_format_fastest`（本项目默认） | **UYVY** | **UYVA** |
| `NDIlib_recv_color_format_best` | P216 / UYVY 等（随源 codec） | PA16 等 |
| `NDIlib_recv_color_format_UYVY_BGRA` | UYVY | **BGRA** |
| `NDIlib_recv_color_format_BGRX_BGRA` | BGRX | **BGRA** |

要点：

- **不要假设「发送 BGRA → 接收就是 BGRA」**；以 `NDIlib_recv_capture_v3` 返回的 `frame.FourCC` 为准。
- **`fastest`**：SDK 尽量不做额外色彩转换，性能与延时通常最优，但多数平台交付 **UYVY** 而非 BGRA。
- **`BGRX_BGRA` / `UYVY_BGRA`**：SDK 会在必要时做转换；需要 BGRA 缓冲时使用。
- **`color_format` 在创建 Receiver 时设定**；运行中切换需重建 Receiver（本项目 UI 在连接前配置）。

#### 与本项目代码的对应

- 发送：[`common/ndi/NdiSender.cpp`](../common/ndi/NdiSender.cpp) 中 `frame.FourCC = NDIlib_FourCC_type_BGRA`
- 接收：[`common/ndi/NdiReceiver.cpp`](../common/ndi/NdiReceiver.cpp) 中 `mapColorFormat()` 映射 UI 选项；`processVideoFrame()` 将 `frame.FourCC` 传给渲染层
- 渲染：[`common/render/Dx11VideoRenderer.cpp`](../common/render/Dx11VideoRenderer.cpp) 按 FourCC 选择 UYVY 或 BGRA shader

此前 **Fastest 下收到 UYVY 却按 BGRA 渲染导致偏色**，即因未区分发送 FourCC 与接收交付格式所致；修复后渲染路径已按实际 `frame.FourCC` 分支处理。

### 5.2 Alpha 透明度测试架构

用于验证 NDI 带 Alpha 通道的推拉流与本地渲染混合，不依赖屏幕采集（DXGI 帧几乎全不透明）。

```
NDISender                          NDI (SpeedHQ)                    NDIReceiver
┌──────────────────┐              LAN              ┌─────────────────────────────┐
│ AlphaTestPattern │──BGRA async──►                 │ NdiReceiver::recvLoop       │
│  alphaScale 滑动条│                              │  UYVA → convertUyvaToBgra   │
│  发送 Alpha 统计  │                              │  其他 FourCC → copy         │
└──────────────────┘                              └───────────┬─────────────────┘
                                                              │ videoCallback (recv 线程)
                                                              ▼
                                                  VideoPreviewWidget::submitFrame (mutex)
                                                              │
                                                  QTimer 33ms → onRenderTick (UI 线程)
                                                              ▼
                                                  Dx11VideoRenderer
                                                    棋盘格 + previewAlphaScale 混合
```

#### 发送端（Alpha 测试图模式）

| 组件 | 说明 |
|------|------|
| `AlphaTestPattern` | 生成四边标识条、半透明圆、不透明块、全透明背景等 BGRA 测试图 |
| `patternAlphaSlider_` | 0–100% 滑动条，经 `alphaScale_` 缩放所有非零 Alpha 通道 |
| `NdiSender::sendVideoBGRA` | 双缓冲 ping-pong，避免 async 发送与填充竞争 |
| `sentAlphaMin_` / `sentAlphaMax_` | 推流线程每帧稀疏网格采样，状态栏显示 **发送 Alpha: min~max** |

限制：Alpha 测试图模式自动锁定 **High Bandwidth**；HX H.264 不保证 Alpha 透传。

#### 接收端（Alpha 可视化）

| 组件 | 说明 |
|------|------|
| `convertUyvaToBgra` | Fastest 下 SpeedHQ 带 Alpha 常以 UYVA 交付，转为 BGRA 供渲染/PNG |
| `alphaCheckerCheck_` | 启用棋盘格背景，透明区域可见 |
| `previewAlphaSlider_` | **仅预览**：强制按 Alpha 与棋盘格混合，用于验证渲染路径（NDI 丢 Alpha 时仍可测混合） |
| Alpha 统计 | 约每 15 帧、步进 64px 采样 **Alpha: min~max** 与 **FourCC** |

#### Sender Alpha vs Receiver 预览 Alpha

| 控件 | 作用域 | 说明 |
|------|--------|------|
| Sender **测试图 Alpha** | NDI 推流数据 | 无本地预览；看状态栏 **发送 Alpha** 或 Receiver 统计 |
| Receiver **预览 Alpha 倍增** | DX11 预览混合 | 不改变 NDI 帧；调低可验证棋盘格叠加逻辑 |

若 Receiver 在预览 Alpha=100% 时仍显示 **Alpha: 255~255**，说明 NDI 路径未保留透明，应使用 Fastest + 关闭硬件解码，或依赖预览 Alpha 倍增做渲染侧验证。

### 5.3 UI 线程与预览性能

**问题（已修复）**：旧实现每帧通过 `QMetaObject::invokeMethod(..., Qt::QueuedConnection)` 将完整视频帧投递到 UI 主线程，并做全像素 Alpha 扫描，导致窗口拖动等交互严重卡顿、丢帧计数飙升。

**现行设计**：

| 线程 | 职责 |
|------|------|
| 接收线程 (`NdiReceiver::recvLoop`) | 拉流、UYVA 转换、拷贝帧；`videoCallback_` 内直接 `submitFrame` |
| `VideoPreviewWidget` | `submitFrame` 在 mutex 下写入 `displayFrame_`；`frameUpdated_` 置位 |
| UI 线程 (`QTimer` 33ms) | `onRenderTick` 仅在 `frameUpdated_` 或 `renderDirty_` 时上传纹理并 `Present` |
| 统计 UI (`QTimer`) | Alpha/FourCC 稀疏采样，不阻塞每帧路径 |

**渲染**：`Dx11VideoRenderer::present` 使用 `Present(0, 0)`（不等待垂直同步），降低 UI 阻塞。

联调步骤见 [05-联调验证指南 §测试 6](05-联调验证指南.md#测试-6alpha-透明度推拉流)；功能与变更记录见 [06-功能清单与变更记录](06-功能清单与变更记录.md)。

## 6. 关键 API 参考

### Sender

```cpp
NDIlib_send_create_t send_create{};
send_create.p_ndi_name = "NDISender Demo";
send_create.p_groups = "Public";
send_create.clock_video = true;
send_create.clock_audio = false;
auto pSend = NDIlib_send_create(&send_create);

NDIlib_video_frame_v2_t frame{};
frame.xres = 1920;
frame.yres = 1080;
frame.FourCC = NDIlib_FourCC_type_BGRA;
frame.frame_rate_N = 60000;
frame.frame_rate_D = 1001;
frame.p_data = bgraBuffer;
frame.line_stride_in_bytes = width * 4;
NDIlib_send_send_video_v2_async(pSend, &frame);
```

### Receiver

```cpp
NDIlib_recv_create_v3_t recv_create{};
recv_create.color_format = NDIlib_recv_color_format_fastest;
recv_create.bandwidth = NDIlib_recv_bandwidth_highest;
recv_create.allow_video_fields = true;
auto pRecv = NDIlib_recv_create_v3(&recv_create);
NDIlib_recv_connect(pRecv, &source, nullptr, 0);

NDIlib_video_frame_v2_t video{};
switch (NDIlib_recv_capture_v3(pRecv, &video, &audio, nullptr, 1000)) {
case NDIlib_frame_type_video:
    // 处理并 NDIlib_recv_free_video_v2
    break;
}
```

### Frame Sync（平滑播放）

```cpp
auto pSync = NDIlib_framesync_create(pRecv);
NDIlib_framesync_capture_video(pSync, &video, NDIlib_frame_format_type_progressive);
// 渲染后 NDIlib_framesync_free_video
```

### 延时优化

1. 发送：`NDIlib_send_send_video_v2_async` + 编码器低延时（无 B 帧）
2. 接收：`NDIlib_recv_color_format_fastest`，禁用 Frame Sync
3. 实时处理队列，避免堆积
4. 预览：接收线程写缓冲 + UI 定时刷新（~30fps），避免每帧跨线程投递

## 8. 风险与依赖

1. Advanced SDK Trial 未获批时可用免费 SDK 跑 High Bandwidth
2. HDR 发送需 Advanced 授权，首期 SDR 8-bit
3. 全屏独占游戏可能 DXGI 黑屏
4. FFmpeg 6.1 为可选 fallback，默认 NDI SDK 解码
